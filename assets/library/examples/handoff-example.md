# 示例 · 项目交接（任务上下文）

> 模板：`assets/templates/docs/项目交接.md`（六小节结构由它定义）
> 落盘：`docs/项目交接.md` ｜ 产出与刷新：`/context-handoff`
> 会话开场由 session-start-context hook 探测加载。

## 为什么这份长这样

它的读者是**下一个会话里的 AI 和你自己**：只写能从证据里核对的东西。
最值钱的一节是"已决策"里的**否决记录**——没有它，第三次开会话时
又会有人提议同一个方案，再讨论一遍。

## 章节骨架

```
文档头（谁接着干要看这里：六小节各写什么）
1 目标与验收标准      验收判据要能逐条核对，不写"体验流畅"
2 已完成项（附证据路径）  每条挂一个可打开的路径或命令输出
3 已决策（含被否决方案与理由）
4 未决问题            写清"卡在哪、需要什么才能继续"
5 下一步              精确到文件与操作
6 关键文件清单        本任务真正会碰的 8–15 个路径
```

## 片段 2 · 3 已决策：否决项和理由一起留

```markdown
| 决策 | 结论 | 理由 / 否决的方案 |
|------|------|------------------|
| 幂等键存储 | 单表 + 按 key 哈希分片 | 否决「加分布式锁」：重放要能回放首次响应，锁给不了 |
| 金额类型 | 全链路整型「分」 | 否决 `BigDecimal`：序列化到前端浮点丢精度，历史事故 2 起 |
| 退款入口 | 只保留按行退 | 否决「客服手工覆盖金额」：无审计留痕，已在 delta 里 REMOVED |
| 上线节奏 | 灰度 10% → 50% → 全量 | 否决一次性全量：新退款链路无先例，需留回滚窗口 |
```

## 最容易走形的三处

1. "下一步：继续开发" → 新会话仍要重问一遍上下文，交接等于没做。
2. 已完成项不挂证据路径 → 无法核对，只能重跑一遍验证。
3. 只记采纳的决策，被否决的方案连同理由一起丢 → 同一个坑再讨论三次。
