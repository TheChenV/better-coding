## 片段 1 · 5.2 核心业务逻辑：编排 + 补偿，逐步可核

```markdown
**BR-ORD-01 提交订单**（`POST /v1/orders`）
1. 校验幂等键（命中 → 直接返回首次结果，见 5.4）
2. 读地址快照（不属于本模块 → 调 user 服务，失败 404 MP-4001）
3. 逐 SKU 锁定库存（一次批量调用，避免中途部分锁定）
4. 计算金额：商品总价 − 优惠券抵扣 + 运费，单位「分」全程整数
5. 落订单主表 + 明细表，状态 `PENDING_PAYMENT`，写 `deadline_at`
6. 发领域事件 `order.created`（供超时关单消费）

补偿：步骤 3 成功而 5 失败 → 立即释放库存 + 回退优惠券占用，
      补偿失败落 `compensation_retry` 由定时任务兜底（≤3 次）。
```

## 片段 2 · 5.4 幂等性设计：每个写端点一行，不写"前端防抖"

```markdown
| 端点 | 键来源 | 去重窗口 | 命中重放响应 |
|------|-------|---------|-------------|
| POST /v1/orders | `X-Idempotency-Key`（客户端 UUID） | 24h | 200 + 首次订单体 + `MP-9004` 标头提示 |
| POST /v1/coupons/{id}/claim | 同上 | 24h | 200 + 首次券实例 |
| POST /v1/payments | 服务端以 orderId 生成 | 至支付终态 | 202 + 原支付单 |
存储：`idempotency_key(key, scope, first_response, created_at)`，
按 key 哈希分片；首次响应必须可回放，否则等于没做幂等。
```

## 片段 3 · 9.3 错误码：分段号段 + 与状态码绑定

```markdown
通用号段
| 错误码 | HTTP | 描述 |
|-------|------|------|
| MP-9002 | 400 | 请求参数校验失败 |
| MP-9003 | 400 | 缺少必填头 X-Idempotency-Key |
| MP-9004 | 409 | 幂等键已处理，请勿重复提交 |
| MP-9001 | 503 | 下游中台不可用，当前为降级响应 |

本模块号段（orders = 4xxx）
| MP-4003 | 409 | 优惠券不可用（已用/过期/不满足门槛） |
| MP-4005 | 409 | 订单当前状态不允许此操作 |
| MP-4006 | 409 | 该订单已存在退款申请 |
```

异常四类都要覆盖：参数类 / 权限类 / 状态冲突类 / 依赖不可用类。
