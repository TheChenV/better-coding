## 为什么这份长这样

PRD 是"做什么 + 怎么算验收 + 优先级"，一份统一 MRD 会拆成多份
（每应用一份）。P99 / SLA / API 字段一律前向引用 ARCH 与 SPEC，
写了就改不回来；Section 4 则是交互原型工程的 1:1 基准，漏页面
后面整条链都漏。


## 片段 1 · 1.4 应用类型声明：一句话定住两条链

```markdown
> **应用类型**：`Full-Stack`
+ 前端：React SPA（Vite + TypeScript），CDN 静态托管；一期不做 SSR。
+ 后端：`shop-gw` 薄网关，只做鉴权、聚合、会话与限流重试，
  不拥有任何业务主数据（主数据在 mall-core）。
+ 不设 BFF 层：SPA → shop-gw → mall-core REST，链路只有一跳编排。
```

判据：声明为 Full-Stack → 必须有 Section 4 + 交互原型工程；
声明为 Backend-Only → 4 章整节写"跳过"，不留白。

## 片段 2 · 3.2 用户故事：P0/P1 各 ≥2 条 Gherkin

```markdown
##### US-CART-001：把 SKU 加入购物车（P0）
作为消费者，我想把选中的 SKU 加进购物车，以便后面一次结清。

场景：库存充足的 SKU 加入未满的购物车
  Given 用户 "U-1001" 的购物车已有 3 种不同 SKU
  And SKU "SKU-A" 可售库存 = 20
  When 加入购物车 SKU "SKU-A" 数量 2
  Then 购物车出现 SKU "SKU-A" 且数量 = 2
  And 购物车 SKU 种类数变为 4，角标同步 +1

场景：同一 SKU 重复加入按数量合并
  Given 购物车已含 SKU "SKU-A" 数量 2
  When 再加 SKU "SKU-A" 数量 3
  Then 该行数量变为 5，且不产生第二行

异常场景
- [ ] 页面加载与加购之间库存归零 → 拒绝并提示（错误码见 SPEC-API）
- [ ] 网关超时但中台写成功 → 携同一幂等键重试，不产生重复行

边界条件
- [ ] 数量必须为 [1, 99] 的整数；库存 >99 时购物车层仍按 99 截断
- [ ] 单用户购物车 ≤ 50 种 SKU，第 51 种拒绝
```

写法要点：异常与边界各带"预期行为"，不写"待补充"。

## 片段 3 · 4.2 页面-模块-US 映射：三向都能追

```markdown
| 页面路由 | 模块 | 相关用户故事 |
|---------|------|-------------|
| `/products/:id` | M-01 商品浏览, M-02 购物车 | US-BROWSE-002, US-CART-001 |
| `/checkout` | M-03 订单, M-05 优惠券, M-06 用户 | US-ORD-001, US-COUPON-003 |
| `/orders/:id/refund` | M-03 订单 | US-ORD-005 |
```

3.3 模块间依赖契约固定四列，第 4 列写**调用场景**而不是 SLA；
Perspective 1（我依赖谁）与 Perspective 2（谁依赖我）逐行镜像。

## 最容易走形的三处

1. 在 PRD 里写 DTO 字段表 → 归 SPEC-API，PRD 只到能力/契约级。
2. 4.1 页面清单比原型工程多两页 → 1:1 基准失效，环节 4 无从核对。
3. US 编号不带应用前缀，跨应用对账时同一 `US-001` 出现三次。
