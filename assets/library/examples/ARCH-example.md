# 示例 · ARCH（架构设计文档 + ADR）

> 模板：`../L0-universal/spec-templates/ARCH-template.md`
> 落盘：`docs/arch/ARCH-MP-01.md` ｜ 产出：环节 2 `/create-architecture`

## 为什么这份长这样

ARCH 是需求语言到技术语言的唯一转换层：每个决策都要留下
"至少两个候选 + 淘汰理由"，否则半年后没人知道当初为什么不选另一个。
规模数字必须由业务量推导而来，而不是抄一份行业惯例。

## 章节骨架

```
0 文档信息       0.1 版本/状态 0.2 评审记录
1 应用概述       1.1 背景与目标 1.2 应用组合与角色 1.3 C4 Context 1.4 C4 Container
                 1.5 应用间依赖契约 1.6 模块级设计前置信息
2 后端架构与选型  语言 / Web 框架 / 通信协议 / 数据格式 / API 风格（每项 ≥2 候选）
3 前端架构与选型  （Full-Stack 必填）工程结构 / 性能预算 / 部署策略
4 前后端通信      通信分层 / 网关选型 / 错误信封 / 幂等与追踪透传
5 中间件选型      MQ / 关系库 / 缓存 / 对象存储 / CDN / 日志 / 可观测 / 治理 / 定时任务
附录  A 通用约定  B 范围边界  C 跨应用一致性  D 嵌入式 ADR 模板  E 检查点清单  F ADR 汇总
```

## 片段 1 · 1.1 规模与推导：数字带来源列

```markdown
| 维度 | 目标值 | 来源 |
|------|-------|------|
| DAU | 30,000 | MRD §3.1 |
| 日订单数 | ~3,600 | MRD §3.2 |
| 日 PV | ~300,000 | 推导：DAU × 10 页/人 |
| 平峰读 QPS | ~105 | 推导：日 PV ÷ 活跃 8h 秒数 |
| 大促峰值 QPS | ~1,200 | 推导：平峰 × 10 |
| 读写比 | 95 : 5 | 行为模型 |
| 可用性 | 月度 ≥ 99.9% | 业务侧承诺 |
| 读 P99 / 写 P99 | ≤ 500ms / ≤ 1s | 本文件定义（MRD 不写） |
```

没有"来源"列，容量数字就无法复核——这一列是本文档可信度的骨架。

## 片段 2 · 2.x 选型：候选 + 淘汰理由 + ADR 锚点

```markdown
### 2.3 通信协议
| 候选 | 优势 | 劣势 | 判定 |
|------|------|------|------|
| REST over HTTPS + JSON | 团队熟、网关与客户端零改造、契约可静态校验 | 无流式 | ✅ 采用 |
| gRPC 内部直连 | 强类型、低序列化开销 | 浏览器侧需代理，一期无收益 | ❌ 二期再评估 |
| GraphQL | 前端自助聚合 | 权限面难收敛、缓存语义复杂 | ❌ 不采用 |
→ 理由沉淀见 ADR-001。
```

## 片段 3 · 附录 F ADR 摘要：结论、替代方案、后果

```markdown
# ADR-002：写操作统一要求幂等键
日期 2026-05-27 ｜ 状态：已采纳 ｜ 决策者：架构 + 订单模块负责人
上下文：用户在弱网下重复提交下单/支付/领券；渠道回调会重推。
决策：所有非 GET 端点要求 `X-Idempotency-Key`（UUID v4），
      服务端以 `idempotency_key` 表去重，窗口 ≥ 24h，
      命中重放返回首次结果 + 业务码 `IDEMPOTENT_REPLAY`。
替代方案：(a) 前端按钮禁用 —— 挡不住回调重推，淘汰；
         (b) 数据库唯一约束兜底 —— 无首次结果可回放，淘汰。
后果：多一张写热点表（按 key 哈希分片解决）；
      测试面增加"重放"一类，已进 SPEC-TEST 的 P0 场景。
```

## 最容易走形的三处

1. C4 只画到 Context（一张框图）→ 判据要 ≥ L2 Container。
2. 选型表每行只有一个候选 → 等于没做决策，回头无法追溯。
3. Full-Stack 项目漏掉第 3、4 章 → 前端与通信无依据，
   SPEC-FE 与 SPEC-API 只能各写一套。
