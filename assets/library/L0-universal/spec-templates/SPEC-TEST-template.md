## 2. E2E测试策略

### 2.1 E2E场景设计原则

> **来源**: Addy Osmani agent-skills + Superpowers verification-before-completion

1. **只覆盖完整业务流程** — 从用户入口到终态确认，不测内部实现
2. **按用户价值排优先级** — P0 = 核心交易链路，P1 = 辅助功能，P2 = 边缘场景
3. **数据隔离** — 每个测试用例使用独立测试数据，`beforeEach` 重置状态
4. **等待策略** — 禁止硬编码 sleep，使用元素/网络/状态等待
5. **每个流程至少覆盖 1 个正常路径 + 1 个异常路径**

### 6.1 数据策略与工具

### 6.2 测试数据管理规范

> 测试数据是测试可靠性的基石。数据隔离、生成、清理三个环节必须闭环。

**数据隔离原则**:
- [ ] 每个测试用例使用独立数据，禁止共享可变状态
- [ ] 测试库与开发库/生产库物理隔离
- [ ] 并行执行时数据不串扰（按测试套件分配数据域）

**数据生成规范**:
| 数据类型 | 生成方式 | 幂等性 | 示例 |
|---------|---------|--------|------|
| 主数据（用户/商品） | Seed 脚本 | 幂等（可重复执行） | `seed_users.sql` |
| 业务数据 | Factory 动态生成 | 每次新建 | `UserFactory.create()` |
| 边界数据 | 显式定义 | 固定值 | 空字符串/超长/特殊字符 |
| 时间相关数据 | 相对时间生成 | 可重复 | `now() - 1d` |

**数据清理策略**:
| 层级 | 策略 | 说明 |
|------|------|------|
| 用例级 | 事务回滚 | 每个用例结束后回滚，速度最快 |
| 套件级 | Truncate 重建 | 测试套件结束后清空表 |
| 环境级 | 容器重建 | 测试环境每次自动重建 |

**数据版本管理**:
- Seed 脚本纳入版本控制，与代码同步变更
- 数据变更通过迁移脚本管理，禁止手工改库

### 6.3 测试数据三件套

> 对于集成测试和契约测试，使用以下三件套定义测试数据：

#### case.json - 测试用例定义

```json
{
  "testId": "TC-001",
  "description": "[测试场景描述]",
  "target": {
    "method": "[POST/GET/...]",
    "path": "[/api/v1/resource]",
    "headers": {}
  },
  "input": {
    "body": {}
  },
  "expected": {
    "status": [200],
    "body": {
      "code": [0]
    }
  }
}
```

#### setup.sql - 测试数据准备

```sql
-- 清理旧数据
DELETE FROM [table_name] WHERE [condition];

-- 插入测试数据
INSERT INTO [table_name] ([columns]) VALUES ([values]);
```

#### verify.sql - 测试数据验证

```sql
-- 验证数据库状态
SELECT COUNT(*) AS count FROM [table_name] WHERE [condition];
-- 预期: count = [expected_count]
```
