# 代码注释规范

> 来源：Karpathy "Code is the best documentation" + Conventional Comments + Harness 课程第 2 课。

## 核心原则

- 注释的目的是解释 **为什么（Why）**，而非 **做了什么（What）**
- 好的代码本身就是文档 — 如果代码需要注释才能看懂，先尝试让代码更清晰
- 临时注释必须标注 `TODO(姓名): 原因` 和过期条件

## 必须注释的场景

1. **公共 API 文档** — 函数签名、参数、返回值、异常
2. **非直觉的业务规则** — 为什么金额用 Decimal 而非 float
3. **Workaround** — 为什么不用"正常"方式实现，标注关联 Issue
4. **复杂算法** — 核心思路，不是逐行翻译

## 禁止的注释

- ❌ 无意义注释：`// 设置名称` 对应 `setName()`
- ❌ 注释掉的代码残留 — Git 有历史，删除即可
- ❌ 日志式注释：`// 2024-01-01 张三修改` — 用 git blame
- ❌ TODO 无负责人、无过期条件

## 注释格式

```
// WHY: <为什么这样做>
// TODO(姓名): <待办事项> — 过期条件: <什么时候应该删除/修改>
// HACK: <临时方案> — 关联: <Issue #NNN>
```
