# 领域词汇本（Domain Glossary）

> 本文件是项目领域术语的**单一权威台账**（状态化设计：无术语时表为空属正常初态，随项目进展由同步与追问流程写入，禁止编造）。
> 来源：对齐开源社区 grill-with-docs 的"共享语言"实践——术语一次定义、全程复用，消除跨会话重复解释与同物多名漂移。

## 使用纪律（强制）

1. **先查后问**：AI 遇到领域词（业务概念、状态名、缩写），先查本表；已登记的直接使用定义，不得再向用户提问"X 是什么"
2. **共识即落盘**：追问/评审/对话中一旦与用户确认了术语定义，当场写入本表（随 3 步同步步骤 1 落盘），不得只留在对话里
3. **同物一名**：同一概念只允许一个名称；发现混用（如"积分"与"星币"）→ 提请用户裁定统一名，并同步修订相关文档（可走 /harness-analyze 术语维度核对）
4. **代码命名对齐**：代码标识符命名以本表"英文标识"为准；新术语先入表再进代码
5. **定义只来自事实**：定义必须由用户确认或从既有文档（PRD/ARCH/SPEC）推导并标注来源；无法确认的术语不入表

## 通用命名与缩写约定（跨项目默认，除非本项目另行登记覆盖）

| 缩写 | 全称 | 使用场景 | 规则 |
|------|------|----------|------|
| ID | Identifier | 主键、外键 | 代码里统一用 `Id` 而非 `ID` |
| DTO | Data Transfer Object | 层间数据传输 | 仅用于跨层传输，不作领域模型 |
| VO | Value Object / View Object | 领域值对象 / 前端展示对象 | 依上下文区分，二者不得混用同一类型 |
| BO | Business Object | 业务逻辑对象 | 领域层内部使用，不出领域层 |

常见易混淆对（登记本项目术语前先对照，避免同物多名）：`Order`（业务订单）≠ `Transaction`（支付流水）；`User`（自然人）≠ `Account`（登录凭证，一 User 可多 Account）；`Delete`（物理删除）≠ `Remove`（从集合逻辑移除）；`Create`（新建实体）≠ `Add`（加入已有集合）。领域建模常用：`AggregateRoot` / `ValueObject` / `DomainEvent` / `AntiCorruptionLayer`。
