# 代码审查标准

> 来源：Matt Pocock code-review 双轴模型 + Addy Osmani 五维审查体系。

## 双轴审查模型

### 标准轴（Standard Axis）— 代码质量五维度

1. **正确性** — 逻辑正确、边界覆盖、并发安全、错误处理完整
2. **安全性** — 无注入、无硬编码密钥、输入校验、权限检查
3. **可维护性** — 命名清晰、函数精简、无重复、模块边界清晰
4. **性能** — 无 N+1 查询、无循环内 IO、合理缓存、分页处理
5. **可读性** — 代码自解释、必要注释、文件组织清晰

### 规格轴（Spec Axis）— 需求对齐

- 每个 User Story 是否有对应实现
- API 签名是否与契约一致
- 数据模型是否与 DDL 一致
- 错误码是否与 Spec 定义一致
- 分层依赖是否符合 ARCH

## 严重度标签

| 标签 | 含义 | 处理要求 |
|------|------|---------|
| Critical | 阻断性 | 必须修复，不可合并 |
| Major | 严重 | 应当修复 |
| Minor | 一般 | 建议本次修复 |
| Nit | 微小 | 可选修复 |
| Optional | 建议 | 后续迭代处理 |
| FYI | 信息 | 仅供知晓 |

## 输出顺序

**先列风险，再给建议。** 不要先夸再批。
