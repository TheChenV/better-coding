# 性能优化

## 核心理念

> **不要猜测瓶颈在哪，度量它。**
>
> 性能优化四步：识别瓶颈 -> 度量基线 -> 优化 -> 验证提升。
> 没有度量就没有优化。优化后必须有前后对比数据。
>
> 来源：Addy Osmani agent-skills performance-optimization — 度量驱动的性能优化。

## 触发条件

- 用户输入 `/performance-optimization`
- 用户报告性能问题（慢、卡、超时）
- 定期性能治理

## 执行步骤

### Step 1: 识别瓶颈

**后端：**
```bash
# 慢查询检测
# APM 工具 / 数据库慢查询日志
# 接口响应时间 P50/P95/P99
```

**前端：**
```bash
# Lighthouse 评分
# Core Web Vitals: LCP / FID / CLS
# 包大小分析
```

**数据库：**
```bash
# 慢查询日志
# 索引使用情况
# 连接池状态
```

### Step 2: 度量基线

> **优化前必须有基线数据。**

```
性能基线:
- 指标: <P50/P95/P99 响应时间 / QPS / 包大小>
- 当前值: <数值>
- 目标值: <数值>
- 测量条件: <环境/数据量/并发数>
```

### Step 3: 优化（按收益/成本排序）

| 优化方向 | 常见手段 | 预期收益 |
|---------|---------|---------|
| **数据库** | 索引优化、查询优化、分页、缓存 | 高 |
| **后端** | N+1 消除、批量操作、异步处理、缓存 | 高 |
| **前端** | 代码分割、懒加载、虚拟列表、缓存 | 中-高 |
| **网络** | CDN、压缩、HTTP/2、连接复用 | 中 |
| **架构** | 读写分离、分库分表、消息队列 | 高（但成本高） |

### Step 4: 验证提升

```
优化结果:
- 指标: <同基线指标>
- 优化前: <基线值>
- 优化后: <新值>
- 提升: <百分比>
```

## 常见性能陷阱

1. **N+1 查询** — 循环中逐条查询数据库，改为批量查询
2. **缺少索引** — 大表查询无索引，全表扫描
3. **过度渲染** — React 组件不必要的重渲染
4. **大包体积** — 未做代码分割，首屏加载过慢
5. **同步阻塞** — 耗时操作阻塞主线程，改为异步
