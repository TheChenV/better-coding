# 紧急修复流程（Hotfix）

> **使用说明**：根据项目实际紧急修复流程定制。`【__名称__】` 为必填占位，`【__名称__，可选】` 为选填，`【已预填：xx，请核对】` 为 AI 预填项。

## 触发条件

当生产环境出现影响用户的紧急 Bug，需要快速修复并上线时手动触发。

## 紧急程度判定

| 等级 | 定义 | 响应时间 | 示例 |
|------|------|----------|------|
| P0-致命 | 系统不可用/数据丢失 | 【__15 分钟__】 | 【__支付失败、数据错乱__】 |
| P1-严重 | 核心功能异常 | 【__1 小时__】 | 【__下单报错、登录失败__】 |
| P2-一般 | 非核心功能异常 | 【__4 小时__】 | 【__页面展示错误__】 |

## 执行步骤

### Step 1: 问题确认（≤5 分钟）

- 确认问题现象：【__用户反馈/监控告警内容__】
- 确认影响范围：【__受影响用户数/功能范围__】
- 确认复现条件：【__触发条件、环境信息__】
- 确认紧急等级：P0 / P1 / P2
- 通知相关人员：【__技术负责人/产品经理__】

### Step 2: 创建 Hotfix 分支

```bash
# 从生产分支创建 hotfix 分支
git checkout 【__main/master/release__】
git pull origin 【__main/master/release__】
git checkout -b hotfix/【__issue编号__】-【__简短描述__】
```

### Step 3: 根因定位

- 查看生产日志：【__日志平台地址/关键日志关键词__】
- 查看监控数据：【__监控面板地址__】
- 使用系统化调试方法：
  1. 明确预期行为 vs 实际行为
  2. 生成 ≥3 个假设
  3. 逐一验证（最小实验）
  4. 确认根因
- 输出：根因分析报告（一句话描述根因）

### Step 4: 最小化修复

**核心原则：Hotfix 只做最小化修复，不做任何重构或优化。**

- 修复范围严格限制在问题根因
- 不顺手修改其他代码
- 不引入新依赖
- 不改变现有接口契约
- 如果修复方案有风险，优先选择临时规避方案

修复代码要求：
- [ ] 修改行数尽可能少
- [ ] 不改变现有方法签名
- [ ] 添加必要注释说明修复原因
- [ ] 注释格式：`// HOTFIX #【__issue编号__】: 【__修复说明__】`

### Step 5: 快速验证

- [ ] 编译通过
- [ ] 编写/运行针对该 Bug 的回归测试
- [ ] 本地复现场景验证修复有效
- [ ] 验证不引入新问题（相关功能冒烟测试）
- [ ] 代码自审（重点检查：是否最小化、是否有副作用）

### Step 6: 快速审查

- 审查重点（简化版 Code Review）：
  - [ ] 修复是否正确解决根因
  - [ ] 是否有副作用
  - [ ] 是否最小化修改
  - [ ] 是否有安全隐患
- 审查人：【__技术负责人/指定审查人__】
- P0 级别可先上线后补审查

### Step 7: 部署上线

```bash
# 合并到生产分支
git checkout 【__main/master/release__】
git merge hotfix/【__issue编号__】-【__简短描述__】

# 部署（按项目部署流程）
【__部署命令或流程说明__】
```

- 部署后立即验证：
  - [ ] 问题现象消失
  - [ ] 相关功能正常
  - [ ] 监控指标恢复正常
  - [ ] 无新增错误日志

### Step 8: 善后处理

- [ ] 将 hotfix 分支合并回开发分支（避免修复丢失）
  ```bash
  git checkout 【__develop__】
  git merge hotfix/【__issue编号__】-【__简短描述__】
  ```
- [ ] 更新 Issue 状态，记录根因和修复方案
- [ ] 评估是否需要补充 Rule 防止复发
- [ ] 评估是否需要补充测试用例
- [ ] P0/P1 级别需在 【__24 小时__】 内完成事后复盘

## 输出物

- 修复代码（最小化变更）
- 回归测试用例
- 根因分析记录
- 部署验证记录

## 禁止事项

- ❌ 禁止在 Hotfix 中做重构
- ❌ 禁止在 Hotfix 中添加新功能
- ❌ 禁止跳过测试直接上线（P0 可先上线但必须补测试）
- ❌ 禁止未经验证直接部署生产
- ❌ 禁止修改与问题无关的代码
