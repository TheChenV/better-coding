# 术语与编号约定（Naming Convention）

> **定位**：库级参考文档（不落盘项目 `.qoder/`），统一 better-coding 全局术语与编号规则，消除混用。

---

| 统一术语（中文） | 统一术语（英文） | 含义 | 废弃/混用词 |
|-----------------|-----------------|------|------------|
| **环节** | Stage | SDD 流程的一级分区（共 9 个，01-09） | ~~Phase~~（仅在引用 AINative 原始材料时保留原文） |

| **门禁** | Gate | 质量检查点（4 级：L0 前置/L1 step_gate/L2 phase_gate/L3 main_gate） | ~~审核点~~、~~检查站~~ |
| **产物** | Artifact | 环节/步骤的输出物（文件/代码/报告），承载依赖图的节点 | ~~交付物~~（保留"交付前确认"固定短语） |

### manifest 字段名保留说明

manifest.json 中 `specTemplates` 字段名**保留不改**（历史引用链过长、低收益高级联）。该字段对应目录路径 `assets/library/L0-universal/spec-templates/`，两者语义等价：

- `manifest.components.L0.specTemplates` = 模板 ID 列表（如 `MRD-template`、`SPEC-BE-template`）
- `spec-templates/` = 模板文件实际存储目录

## 二、编号规则

### 2.1 环节编号

- 格式：`01`-`09`（两位数字，前补零）
- 含义：SDD 流程 9 个环节（需求澄清/架构设计/模块设计/UI设计/开发实现/联调/集成测试/部署上线/迭代回顾）
- Hooks 配置为横切基础设施，**不占环节编号**（以 H1-H5 独立标注）

### 2.2 步骤编号

| 类型 | 格式 | 示例 | 说明 |
|------|------|------|------|
| 顺序步骤 | `步骤1`、`步骤2`..`步骤n`（纯整数） | 环节7：步骤1-步骤2 | 环节内线性步骤（v9.0.0 全链 22 步：逐环节 3/2/2/2/4/1/2/1/5） |
| 分支/路径 | 纯整数步骤号 + 步骤名标注 | 环节9：步骤2 新功能/步骤3 缺陷分支/步骤4 重构分支 | 分支写进步骤名不进步骤号；步骤号跨分支连续不重置；折叠式渲染只渲选中分支 |
| 复数单元 | 纯整数步骤号，按批次/模块拆区块 | 环节3：步骤1（批次1/N…） | 产出型步骤按批次拆区块（环节 3 按 ARCH 依赖矩阵拓扑分层，默认单批单区块，深度 review 可退回按模块逐区块）；模块/批次维度不入步骤号 |
| 子阶段 | 纯整数步骤号 + 步骤名标注 | 环节5：步骤3 前端实现（五阶段：框架→视觉→交互→数据→优化） | 子阶段写进步骤名不进步骤号 |
| 路由步骤 | `步骤1`（S0 语义） | 环节4/5/9 的步骤1（路径决策/应用类型路由/变更分诊） | 不产出 artifact，只做分诊 |

> **重要**：骨架块头步骤号一律纯整数（harness-verify Check 7c 正则 `·步骤(\d+)` 只捕获纯数字）；`S0`/`S1a`/`S3.1`/`S1#1` **不得用作块头步骤号**，但可作为块头名称或说明列中的**别名标注**保留（如 `【环节4·步骤1 UI路径复检(消费1·3决策)】`；路由步 token 4·1/5·1/9·1 即 S0 语义）；分支/路径/子阶段/复数用步骤名文字 + 折叠式渲染或按批次/模块拆区块表达。

### 2.3 步骤子块头格式

```
【环节N·步骤k 名称】
```

- `N` = 环节编号（1-9，无前补零，因正则捕获单位数）
- `k` = 步骤号（**纯整数**，环节内唯一递增、跨分支/路径连续不重置）
- 名称 = 步骤简短中文名（12 字以内）

示例：
```
【环节1·步骤1 idea→MRD】
【环节5·步骤3 前端实现(五阶段渐进+交付审核)】
【环节9·步骤3 缺陷修复(bugfix 7步内嵌)】
```

### 2.4 PROJECT-LIVE 步骤 token

- 格式：`N·k`（环节号·步骤号，均为纯整数，中点 U+00B7 分隔）
- 用途：步骤 token 写入步骤标题前缀 `#### {emoji} N·k {步骤名}`，配合 harness-verify 按步骤 token 定位区块去碰撞
- 示例：`1·1`、`1·2`、`5·3`、`9·3`

## 三、门禁 4 级体系

| 级别 | 名称 | 挂载位置 | 来源 |
|------|------|---------|------|
| L0 | 前置条件检查 | 环节 `trigger` 字段 | AINative 三层验证第 1 层 |
| L1 | Step 级检查点 | 步骤 `step_gate` 字段 | AINative 三层验证第 2 层 |
| L2 | 环节质量门禁 | 环节 `phase_gate` 字段 | AINative 三层验证第 3 层 |
| L3 | 三道主门禁 | 环节 `main_gate` 字段（spec/implement/release） | better-coding 特有 |

## 四、横切层编号（Hooks）

Hooks 为嵌入环节 1-9 所有环节 Agent 生命周期的"第 0 层"横切质量保障，**不占环节编号**。

| 编号 | 名称 | 说明 |
|------|------|------|
| H1 | 清单设计（事件选型） | 确定场景-事件类型-阻断策略 |
| H2 | 编写 hook 脚本 | .qoder/hooks/ 下创建脚本 |
| H3 | settings.json 绑定 | 注册事件与 matcher |
| H4 | 逐 hook 触发验证 | 端到端确认触发效果 |
| H5 | 宁缺毋假处置 | 不稳定 hook 移除/降级 |
